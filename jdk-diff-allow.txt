# The differences from the JDK that the differential is not allowed to report.
#
#   <case> <kind> <work item> <reason>
#
# `kind` is which of the two things the differential found, and the driver
# checks it against what actually happened, so an entry cannot mask a difference
# of a different kind than the one it was written for:
#
#   java   javac rejects the Java this program prints, so there is nothing to run
#   out    both compiled and ran, and their stdout or exit status differs
#
# `work item` is the plan's Wn that will remove the difference, or `none` when
# there is no such work item: the difference is Teyru's design, or it needs a
# decision from the owner. `none` is a statement, not an omission -- every entry
# here has been looked at, and the reason says what was found.
#
# This file is only read by TestJDKDiff. A difference that *both* drivers see --
# a program whose .expected is the JDK's output and which Teyru gets wrong --
# belongs in known-failures.txt instead, because then the end-to-end suite is
# red as well and the entry has to be deleted when it is fixed.
#
# An entry whose case now agrees with the JDK fails the run, so this file cannot
# rot into a list of things nobody checks any more.

# ---------------------------------------------------------------- outputs

# Teyru runs a class's static initialisers before main; Java runs them at the
# class's first active use (JLS 12.4.1). The `none` is "no plan work item owns
# this", not "nobody is looking at it": two things do. The runtime's own
# publication order (JLS 12.4.2 -- TY_CLS_INIT was set before the initialiser
# ran, so a second thread skipped it and read a null static) has a fix in
# flight, and whether the eager order here should stay is the owner's decision.
# Both programs' .expected are Teyru's order, which is what the suite pins.
# DECIDED by the owner (2026-09-17): the eager order stays. Making it lazy is a
# rewrite of the class-install path for a behaviour no test depends on, and the
# runtime work in flight only makes the lazy path correct for the class monitor
# (JLS 12.4.2), which is what a static cache actually needs. This entry is the
# stated divergence, not an unexplained one.

# The printer does not write a checked exception into the signature of a method
# whose body calls a JDK method that declares one: `t.join()` needs
# `throws InterruptedException`, and Teyru has no compile-time checked
# exceptions for the signature to inherit it from (AGENTS.md §10 names that as a
# known limitation). So javac rejects the printed file and there is nothing to
# run -- the `java` kind, exactly. The fix belongs in emit-java: walk a method's
# body for the calls whose JDK signatures declare a checked exception and add
# the clause. Until then these three are the difference, and deleting an entry
# when it starts agreeing is what the header asks for.
