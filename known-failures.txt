# The cases that fail today, and why.
#
#   <case> <work item> <reason>
#
# A listed case that fails is a known failure: it is reported and it does not
# fail the run. A listed case that *passes* fails the run, so an entry cannot
# outlive the bug it describes -- when the work item lands, the entry goes with
# it.
#
# Both drivers read this file the same way: `go test` in the compiler
# repository (TestPrograms, TestPackages, TestDiagnostics, TestJDKDiff) and
# `sh run.sh` here. An entry is read by name, and the name is what the driver
# prints -- the file's own name for a program, a diagnostic or a package case.
#
# The reason is not optional. A failure nobody has explained is a failure nobody
# can act on, and the work item is what makes the entry temporary rather than
# permanent.
#
# W5 is the string and Unicode semantics, W6 the boxing cache, the HashMap order
# and the exception names and messages, W7 the Java source compatibility. The
# probe programs below are appendix C of the fix plan plus the probes it asks
# for: their .expected is what the JDK printed, so a case here is a place where
# Teyru and Java disagree today, on purpose, with the difference pinned.

# --- appendix C.1: length, charAt, substring, reverse, case mapping, hashCode,
#     HashMap order, boxing identity, exception messages, and the parts that are
#     already right (%.2f rounding, widening, MIN/-1, and so on). The string half
#     is green now -- length, charAt, substring, reverse, hashCode and the case
#     mapping are UTF-16 code units and Unicode 15.0 -- and the one line left is
#     the map's iteration order, which is W6's.

# --- appendix C.2 is green: t231_probe_strings (hashCode, format width,
#     isLetter/isWhitespace, strip, the full-width digits) is not listed here.

# --- the formatting family: already right, and kept right
# t232_probe_format is green: it is not listed here, and it exists so that a
#     regression in %d/%s/%.2f/%e/%g or printf is a failure rather than a silence.

# --- boxing: valueOf does not cache, so == differs for every wrapper type

# --- collection toString: the iteration order of HashMap and HashSet is the
#     JDK's now, so t234_probe_collections is green. t250_map_order is what
#     pins it: one line per rule of the layout, compared against the JDK.

# --- exception messages: the class names are the JDK's now (t251), so what is
#     left here are the three messages the plan does not name. The JDK prints
#     "class java.lang.String cannot be cast to class java.lang.Integer
#     (java.lang.String and java.lang.Integer are in module java.base of loader
#     'bootstrap')" where this prints the first half; the helpful
#     NullPointerException message, which javac records a local variable's slot
#     for; and ArrayStoreException, whose message in Java is the class of the
#     value that did not fit rather than a sentence about the array.
t235_probe_exceptions W6 the class names match java.lang.* now; left are the cast parenthetical, the helpful NullPointerException message and ArrayStoreException's element class

# --- the whitespace and case family is green: t236_probe_unicode (strip, trim,
#     isBlank, isWhitespace, the full-width digits, the Greek final sigma and the
#     dotted-I mapping) is not listed here.

# --- API the checker does not know yet: the string half is declared (codePoint
#     Count, codePointAt, String(char[]), String(int[],int,int), String.join over
#     an array and over an Iterable, String.valueOf(char[]), isSpaceChar,
#     toTitleCase, isSurrogate, charCount), and what is left is the two boxed
#     constructors, which are the boxing work item's declarations.
t237_probe_missing_api W6 new Integer(int) and new Boolean(boolean) are not declared; the string API this probe also asks for landed with W5's write work


# --- `new int[-1]`: javac compiles it and throws at run time, the checker
#     rejects it at compile time
t239_probe_negative_array W7 a negative array size is a compile error here and a run-time exception in Java (plan 1.2)
